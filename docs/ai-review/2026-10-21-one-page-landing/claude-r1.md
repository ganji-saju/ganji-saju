# Claude 판정 — Codex 1차 지적 + 별도 Claude 리뷰어(새 컨텍스트, opus) 지적

두 검토가 겹친 지적이 많아 함께 판정한다. 모든 수용 건은 실패하는 테스트를 먼저 쓰고 고쳤다(전체 테스트 통과: node 단위 0 실패 · vitest 730/730 · tsc 0).

| # | 지적 | 판정 | 반영 |
|---|---|---|---|
| 1 | 정산 크론이 토스만 조회 → 나이스 승인 후 확정 실패 미복구 | **부분 수용** | 크론 자체는 기존 결함·전 상품 공통이라 이번 PR 범위 밖(별도 PR 권고). 랜딩 주문은 ① 확정 실패·결제 후 취소 상태를 운영 경보 메일로 ② 관리자 "결제 확인"(나이스 재조회 + 금액 대조 후 확정) ③ return 의 확정 실패는 "청구되지 않았습니다" 실패 화면 대신 "결제를 확인하고 있어요" 화면으로(이중 결제 방지) |
| 2 | `/r/<토큰>` 이 GA·방문 기록·리퍼러로 샘 | 수용 | `sanitizePath` 가 `/r/*` 를 가림 + 결과 화면 `referrer: no-referrer`. Vercel Analytics 원 URL 수집은 1자 도구라 기존 사주 URL 과 같은 수준으로 둠 |
| 3 | 카드 결제 대기 주문 취소 → 결제 후 취소 상태 | 수용 | 카드 주문 취소 막음(버튼 제거·API 400), paid 갱신 0행이면 운영 경보 |
| 4 | 발송 후 상태 갱신 → 중복 문자·열리지 않는 링크 | 수용 | 상태를 먼저 `sent` 로 잡고(조건부 갱신) 발송, 결과는 별도 기록, "다시 보내기" 분리(상태·첫 발송 시각 불변) |
| 5 | 인스턴스 메모리 잠금·확인한 풀이 버전 미보장 | 부분 수용 | 발송 요청에 상담사가 본 `reportId` 를 실어 현재 풀이와 다르면 409. 잠금은 그대로 두되 상태 경합으로 저장 실패한 원본은 지움(AI 비용 중복 가능성만 남음) |
| 6 | 삭제 중간 실패 시 재시도 안 됨·재생성 원본 남음 | 수용 | 원본 먼저 삭제 후 표시, 다시 만들기 성공 시 이전 원본 삭제 |
| 7 | 1년 보관·열람 제한 미완 | 수용 | 방치된 입금 대기·미발송 주문도 접수 1년 뒤 정리, 결과 화면이 첫 발송 1년 지나면 직접 404 |
| 8 | 윤달 미지원 | 수용 | 음력 선택 시 "윤달에 태어났어요" → 양력으로 바꿔 생성기 전달, 없는 윤달은 안내 |
| 9 | 카드 주문 GA4 구매 누락 | 수용 | GA 쿠키 식별자 + 손님 동의 값 그대로(임의 부여 없음) |
| 10 | 이메일 필수가 고령 손님 장벽 | 보류(제품 결정) | 설계서가 필수로 정함 — 사용자 결정 사항으로 보고 |
| R3 | (리뷰어) 접수 문자 악용 — 아무 번호·이름에 링크 | 수용 | 이름 한글·영문만, 같은 번호 24시간 3건 제한(DB 기준) |
