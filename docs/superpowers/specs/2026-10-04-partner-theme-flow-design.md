# 올해운 노트 — 인플루언서 구매 흐름 전용 디자인 · 설계서

- 작성: Claude Code, 2026-10-04 · 상태: **사용자 검토 대기**
- 앞선 설계: `docs/superpowers/specs/2026-10-04-influencer-landing-design.md`(파트너판·할인·수수료 — 그대로 유지)
- 사용자 결정: 디자인 방향 1번 '모던 다이어리' · 범위 '나'(랜딩 + 생년월일 입력 + 로그인 + 결제 페이지)

## 1. 목적과 성공 기준

- 목적: 인플루언서 링크로 온 손님이 결제창 직전까지 간지사주가 아닌 '올해운 노트' 브랜드 화면만 보게 한다.
- 성공 기준
  1. 랜딩·생년월일 입력·로그인·결제 페이지가 같은 톤(색·글꼴·컴포넌트)이고, 간지사주 헤더·메뉴·로고·하단 탭이 보이지 않는다.
  2. 결제 페이지 금액 = 청구 금액 = 주문 금액(19,200원) — 기존 계산·prepare·주문 기록을 그대로 쓴다.
  3. 간지사주 기존 화면의 디자인·동작은 바뀌지 않는다.
  4. 결제 후에는 기존 신년운세 풀이 화면으로 이어진다(이번 범위 밖).

## 2. 화면 흐름과 주소

```
infl-saju.com/<코드>            랜딩(새 톤)      ── 구매 버튼
 → ganjisaju.kr/partner/go?code=<코드>  파트너 쿠키(7일) 심고
 → ganjisaju.kr/partner/start          생년월일 입력(새 톤)
 → (로그인 안 됨) ganjisaju.kr/partner/login?next=...  카카오·구글(새 톤)
 → ganjisaju.kr/partner/checkout?slug=<사주>           결제 페이지(새 톤)
 → 나이스페이 결제창(변경 불가) → 기존 결제 완료·신년운세 풀이(간지사주)
```

- 로그인·결제를 간지사주 도메인에서 하는 이유: 나이스페이 가맹 등록 사이트, 카카오·구글 로그인 리다이렉트 등록이 간지사주 도메인 기준이다. 새 도메인 등록 없이 기존 설정을 그대로 쓴다.
- `/partner/go` 의 이동 목적지를 기존 체크아웃 → `/partner/start` 로 바꾼다.
- 이미 사주가 있는 로그인 손님도 `/partner/start` 에서 생년월일을 다시 넣는다(이번 범위에서 저장된 프로필 불러오기는 하지 않음 — YAGNI).

## 3. 구성 요소

### 3-1. 테마(올해운 노트)
- 이 흐름의 화면에만 적용되는 레이아웃 `src/app/partner/(theme)/layout.tsx` 와 랜딩이 같은 테마 컴포넌트를 쓴다: 색 토큰 · 글꼴 · 버튼 · 카드 · 하단 사업자 정보.
- 색(초안, 구현 때 대비 4.5:1 이상 확인 후 확정): 바탕 크림 `#FBF7F0` · 글자 딥네이비 `#1F2A44` · 보조 글자 `#5B6478` · 포인트 코랄 `#F26B5B` · 선 `#E8DFD2`.
- 글꼴: 제목 둥근 고딕(라이선스 무료·웹폰트 제공 확인된 것 — 후보 Gmarket Sans / 대체 Pretendard Bold), 본문 Pretendard(이미 사이트에 있음). 외부 글꼴은 이 경로에서만 불러온다.
- 간지사주 전역 요소 숨김: 루트 레이아웃이 그리는 것 중 이 경로에서 보이면 안 되는 것(하단 탭·간지사주 헤더 등)이 있으면 숨기고, 분석·동의 배너처럼 법적으로 필요한 것은 유지(톤만 맞출 수 있으면 맞춤).
- 한자 금지. 로딩 화면이 필요하면 간지사주 12지신 원반 대신 테마 로딩 표시.

### 3-2. 랜딩(새 도메인)
- B안 문구 유지, 디자인만 새 테마로. 구매 버튼 → `/partner/go?code=`.

### 3-3. 생년월일 입력 `/partner/start`
- 입력: 생년월일 · 양력/음력 · 태어난 시간(모름 선택) · 성별. 사주 주소는 기존 `toSlug(BirthInput)`(`src/lib/saju/pillars.ts`)로 만든다 — 간지사주 사주 입력과 같은 규칙이어야 같은 사주로 인식되고 재구매 차단이 맞는다.
- 출생지 등 간지사주 입력의 추가 항목은 기존 신년운세 결과가 같은 사주로 판정되는 최소 항목만 받는다(구현 계획에서 `/saju/new` 의 입력→slug 경로를 읽어 동일성 확인).
- 파트너 쿠키가 없거나 비활성: "지금은 이용할 수 없는 링크입니다" 안내(32,000원 결제로 가지 않게).
- 다음: 로그인 상태면 `/partner/checkout?slug=`, 아니면 `/partner/login?next=/partner/checkout?slug=…`.

### 3-4. 로그인 `/partner/login`
- 카카오·구글 버튼만. 기존 시작 경로(`/api/auth/kakao/...`, `/api/auth/google/start?next=`)를 그대로 호출하고 `next` 로 결제 페이지에 돌아온다. `next` 는 기존 `getSafeNext` 규칙을 따른다(`/partner/` 경로 허용 확인).
- 이메일 로그인·회원가입 폼은 넣지 않는다(간지사주 로그인 화면으로 가는 작은 링크만 둠).

### 3-5. 결제 페이지 `/partner/checkout`
- 파트너판만 다룬다. 금액은 기존 `resolveChargeForUser(파트너판, viewer, null, { env, partner })` 로 계산, 결제 버튼은 기존 결제 컴포넌트(`src/components/membership/toss-membership-checkout.tsx`)와 동의 체크(`src/components/policies/payment-consent-checkboxes.tsx`)를 재사용하고 겉모양만 테마 스타일(래퍼·클래스)로 감싼다. 금액·packageId·expectedAmount 전달 규칙은 기존과 동일.
- 표시: 상품명(2027 운세) · 32,000원 취소선 → 19,200원(40%) · 동의 · 결제 버튼 · "결제·풀이 제공: 간지사주(푸꼬컴퍼니) — 결제창과 카드 명세서에 이 이름이 표시됩니다".
- 이미 구매한 사주: 기존 재구매 차단과 같은 판정으로 "이미 받은 운세가 있어요" + 풀이 보러 가기 링크(간지사주 화면).
- 비로그인 진입: `/partner/login` 으로 보냄. 파트너 없음: 안내만(결제 버튼 없음).
- 기존 `/membership/checkout` 의 파트너 처리는 유지(직접 들어온 경우 대비).

## 4. 범위 밖
- 결제 후 풀이 화면·PDF·결제 완료 화면 · 결제창 · 저장된 프로필 불러오기 · 이메일 로그인 · 인플루언서 본인 화면.

## 5. 오류·경계
- 파트너 쿠키 만료 중간 이탈: 결제 페이지에서 안내, prepare 하드스톱(409)이 최종 방어.
- 로그인 왕복 중 쿠키 유지: 파트너 쿠키는 경로 `/`·7일이라 유지됨.
- 잘못된 생년월일(없는 날짜·음력 윤달 등): 기존 입력 검증 규칙 재사용, 실패 시 입력 화면에 안내.

## 6. 검증
- 단위: 생년월일 → slug 가 간지사주 `/saju/new` 와 같은 값 · 결제 페이지 금액(19,200)·packageId · 비로그인/파트너 없음/이미 구매 분기.
- 가드: 이 경로에 한자 없음 · 간지사주 기존 화면 테스트·E2E 그대로 통과 · 관리자 글자 크기 규칙 영향 없음.
- 실화면: 운영에서 테스트 파트너로 랜딩 → 입력 → 로그인 → 결제 페이지 19,200 → 결제창 19,200(사용자 확인) · 모바일 390px 화면 캡처.

## 7. 사전 준비
- 둥근 고딕 글꼴 확정(무료 웹폰트 라이선스) · 로고(없으면 글자 로고).
